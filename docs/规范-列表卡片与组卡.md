### 1.1 组卡与单卡形态区分（2026-09-08 沉淀——「何时组卡何时单卡」选型判据）

> （≥2 行同质仍一张一张单卡铺）两个方向跑偏；新增设置类卡片先过本节再动手。

**两条硬判据**：
1. **先判形态**：行能套进组卡行规格 = 组卡行；套不进（分段/滑块/文本域/输入）→ 内容卡，
   禁止硬塞组卡（拼不齐的组卡是「凑合」不是整合）；
2. **再数行数**：同质 ≥2 行 → 组卡；恰 1 行 → 按形态选单卡（开关项/内容卡/入口卡）；
   1 行跳转入口 = 默认单条目入口卡（HdsListItemCard），设置页「独立成行」单行组卡是
   登记在案的拍板例外，不扩散；★ 2026-09-18 增**第二例外 = 卡级开关行**（一页多卡各恰
   1 行开关，决明指令定形，见 §4.4）——两条例外均须逐笔登记，不得类推到其他页。

**数据行组卡的行数由数据决定，不换形**（2026-09-09 补，模型选择面板收藏段修复沉淀）：
本节判据管**设置类卡片**的组件选型（组卡 ↔ 单开关卡/内容卡/入口卡）；模型选择面板这类
**数据行组卡**（卡内行 = 数据行，行尾带动作键）行数随过滤结果变化——某服务商在「收藏」分段
只剩 1 行时，渲染的是同一张组卡的**单行退化形态**，不换组件、不换形。理由：①本节三类单卡
都承载不了本面板的行内容（行尾收藏爱心 + 选中打勾 + 左侧整块可点区，`HdsListItemCard`
只承载文本）；②行数会在用户操作中变化（分段内取消收藏 2→1→0），形态跟着变 = 手指下的
布局跳动 + 双代码路径。**判据落点 = 组件选型，不是行数阈值**——数据行组卡恒用同一张卡。

### 1.2 info 提示卡（2026-10-19 首次出现）

- **用途**：页面级只读说明（不承载操作），放页首供全局常显。当前唯一消费方 = 文件夹挂载
  管理页（`entry/src/main/ets/components/settings/MountManagePage.ets` 的 `InfoCard`）。
- **形态**：`sys.symbol.info_circle` 18vp 图标 + 13fp 正文；卡宽 `CARD_PANEL_WIDTH`，
  padding 上下 12 / 左右 14，圆角 CARD_RADIUS（20）；背景 = `app.color.info_card_bg`
  （base `#E8EEFB` / dark `#17223A`）。
- **配色**：图标色 = `usageAccentColor`（项目主蓝），正文色 = `cardTitleColor()`；
  正文 `layoutWeight(1)` 吃满剩余宽，顶部对齐。
- **正文可随页面状态换内容**（当前 = 是否含读写挂载）：在 `@Builder` 内直调页面方法现读
  状态（先例 `MountManagePage.mountInfoText`），禁改成 `@Builder` 值参快照；但必须保持
  只读、不放按钮。
- **新页面复用先读本节**，直接复用本形态，**勿自造第三色**（图标与正文只用上述两个既有
  语义色）。

### 1.3 淡染卡（语义底色卡，2026-10-25 立——表单重构 UI 提案拍板笔）

> 来源：`docs/设计-表单重构新增样式候选-20261025.html` 的 K2 项。**同时承接原提案「反转深卡」
> （K3，页内暗块）的通用场景**——决明 2026-10-25 拍板「反转卡用淡染代替」，本工程不做深色
> 反转卡的通用形态（否决理由见 §1.4）；**三页点名例外 = `NetworkSettingsPage` 当前出口卡
> （2026-10-25 真机反馈）+ `WebServiceSettingsPage` 状态首卡（2026-10-26 决明「只改 web 卡」）
> + `PyRuntimePage` 运行环境卡（2026-11-16 决明「改 python」首卡渐变笔）**——三卡均走固定深色
> 渐变 + `Theme.HERO_CARD_*` 单源，不走 `tintCardBg`；第四页仍须决明点名。

- **用途**：一页里挑**一张**卡，卡底掺语义色做渐变，充当「这张卡有一个值得先看的数」的视觉
  锚点（余额、服务商身份）。它替代的是「靠加大加粗制造重点」，不是替代任何现行卡型。当前出口
  卡已改深色卡，不再属于本族。
- **判据三条**（缺一不可）：①该卡是整页信息重心；②一屏**最多一张**；③卡内不放「只有暗底才
  成立」的元素（白字、白色分隔线、反白图标）。
- **形态**：几何完全沿用同页自绘卡（`CARD_PANEL_WIDTH` / 圆角 CARD_RADIUS（20）/ padding 与邻卡一致），
  **只换底色**——不加投影（§1.4）、不加第二层描边、不改圆角、字号。边框保留
  `cardBorderColor()`，不因染色而撤。
- **色值单源** = `Theme.tintCardBg(kind, mode)`（三档 × 双档，消费侧禁写 hex、禁临时调淡）：

| kind | 语义 / 用在 | 浅色底 | 深色底 | 底 vs 卡面（浅 / 深） |
|---|---|---|---|---|
| `brand` 蓝 | 身份、品牌、信息型头卡 | `#DFE6FA` | `#1C2747` | 1.25 / 1.16 |
| `positive` 绿 | 余额、连通正常、额度充裕 | `#CDE8D8` | `#203B2D` | 1.30 / 1.40 |
| `danger` 红 | 危险操作区、异常指标 | `#F8E4E6` | `#402227` | 1.22 / 1.20 |

- **取值规则**：浅色 = 语义色实色叠白取整（蓝 14% / 绿 **24%** / 红 14%）；深色 = 20%（绿红）/ 22%（蓝）叠 `#1C1C1E`
  ——**同一比例在深色上只有 1.10 出头，读作没上色**，故深色单独反推。验收线 = 底 vs 卡面
  **1.16~1.34**（★ 2026-10-25 真机反馈「淡染淡了一点」后自 1.10~1.20 上移：原下限是按「白卡 vs
  页底 1.10」类推定的，实测 1.17 在那个距离上仍读作「白卡泛了一点点光」——染色卡要成立，得比
  「白卡与页底的距离」再高一级；上限仍防大面积色块压住正文，卡上文字是深色主文字，1.30 量级
  影响不到正文对比。★ **2026-10-26 余额卡渐变笔再上移上限 1.28 → 1.34**：绿档满染端到 1.30
  越旧上限，实测「渐变不够明显」的真因见下条）。
  ★ **2026-10-26 只改绿档，且改的是色相不是浓度**（决明「底色可以再绿一些」）：原 `#DFEFE9`
  色相 **H157**（与徽标成功档 `#1C8C61` 同族，青绿），人眼读作「薄荷灰绿」——「不够绿」的
  诉求落在色相上，不在深浅上，单加浓度只会得到更浓的灰绿。现值 `#CDE8D8` = **H144 正绿**、
  色度 16 → 27、明度**压**（1.19 → 1.30，不是提——提亮会更白、更不绿，同时让渐变更弱）。
  蓝 / 红两档逐字不动（头卡渐变无反馈）。
  卡上文字仍用官方语义色（`font_primary` / `font_secondary` 一族，深浅自动翻），不为染色另开字色。
- **与卡底透明度档的关系**：首版**跟随** `PREF_CARD_ALPHA_LEVEL_KEY` 叠 alpha（与全站中性卡同
  口径，避免用户调低透明度后淡染卡成为唯一不透的卡）；若真机确认低档位下染色被冲淡到读不出，
  再改「淡染卡恒实色」并登记，**不许多页各写一套**。
- **实现形态**：卡底终端色 → 卡底基准的线性渐变（2026-10-25 反馈二笔改为**左上满染 →
  右下渐白**三停，angle 135；★ 2026-10-26 起绿档单独一套三停结构，见下方「两档结构不同」）。渐变若与光感材质或档位叠 alpha 冲突，回退终端色平铺——渐变是观感

### 1.5 卡脚（2026-10-25 立——表单重构 UI 提案 K5 项，决明拍板采纳，附边界）

> 治什么：有些结论属于「整张卡」而不是「某个字段」——「以上价格对所有时段生效，最多添加 6 个时段」「本卡配置随保存键一起落库」。塞进字段说明会把字段与结论混为一谈；挂在卡头又会抢标题。

- **用途**：整卡级结论 / 生效范围 / 上限说明。**不是字段说明**（字段说明贴自己那个框下方，§4.5 判据不变）。
- **硬边界（先过这条）**：**仅「本卡无操作按钮行」的纯展示卡 / 参数卡可用卡脚**。本卡带操作按钮行时，说明仍走宪法「功能设置卡布局次序」——**说明小字置于按钮行上方**，禁改 footer。理由 = 那条宪法针对的正是"按钮前要先读到什么"，卡脚是这个场景的**补位**，不是取代。
- **形态**：hairline 上边线（`cardBorderColor` 同族）+ 上间距 10、下不额外留白；文字 13fp（`CARD_NOTE_FONTSIZE`）× `cardDescColor()`；左右与卡内容同缘。
- **条数上限**：一卡最多一条卡脚、最多 2 行；超了就是页面信息该进帮助中心，不是加第三条。
- **不做**：卡脚里放按钮 / 链接 / 徽标（它只读）；不用卡脚承载错误态（错误走提示条或字段 errorText）；不把它做成跨页通用 footer 组件——本形态允许各页自绘，**禁止为它新开公共件**（反碎片③：纯转接壳）。
- **已落地消费面**：`PriceTemplateEditPage` 名称卡（批 2 首个）、`MemoryEditPage` 记忆卡
  （2026-10-25 批 6：卡脚 = 来源 + 上次更新；本卡无按钮行，合规）、`FeedbackPage` 环境信息卡
  （2026-10-25 批 9：卡脚 = 第三方送达与隐私政策出处；本卡无按钮行，合规）。

### 3.1 彩底图标同心判据（2026-10-26 同心笔）

**判据**：彩色圆角矩形底图标（`iconBg` 行）的**底形中心到卡片左边**应等于**底形中心到卡片上边**
——两者相等时，底形中心落在卡片圆角圆心 (CARD_RADIUS, CARD_RADIUS) 的 45° 对角线上，视觉上
「弧线包着图标走」，首行与末行都读作同心。

**禁止的旧判据**：2026-10-20「居中笔」曾按「图标到左边界 = 图标到右侧文字」调（左右等距），
那是「图标在自己的留白里居中」，与同心是两把尺子——左右等距会把圆推到离左 8vp，而上留白
18vp（卡 pad 4 + 行高 64 内居中 14），偏心 10vp 即「圆角和图标对不上」的观感来源。**勿以
「视觉左右等距」为据回退本笔**（沿革见 `docs/变更记录.md` 一千九百三十节）。

**算式**（改行高 / 图标尺寸 / 卡 padding / 间距时必须重算）：视觉左边距 = 行缩进 4 + 行内左 pad 8
+ translate x；上留白 = 卡 pad 4 +（行高 − 图标高）/2。当前 **38vp 图标 / 60vp 行高 → 两者均为
15vp**（translate 取 +3），标题左缘 = 12 + 38 + 16 = **66vp**，分割线同值（视觉底形右缘 53 + 间距 13；
2026-10-27 放大左移笔。此前 36/64 → 18/18、translate +6 的算式随之退役）。无副标题的彩底行同走
60（存储分类 6 行原 56 档上留白仅 14、与左距 18 偏心 4，已一并收口）。

**判据的适用范围（2026-10-26 同心补全笔）**：本条不是「设置入口图标专用」，**凡卡内带底的
图形件**都按同一算式求同心——名单与各自取值：

| 件 | 尺寸 / 圆角 | 垂直基准 | 同心做法 | 结论 |
|---|---|---|---|---|
| 设置入口图标（组卡行） | 38 / 19（圆） | 行高 60 内居中 → 上留白 15 | translate x:+3 | 视觉左距 = 上留白 15 |
| 设置入口图标（整行一张卡） | 38 / 19 | 卡 padding 16 → 上留白 16 | 无偏移 | 左距 = 上距 16（卡自身对称；内容自适应行随文本行高微移 ≤2） |
| 会话卡身份徽章 | 36 / 12 | 内容区 48 内居中 → 上距 22 | translate x:+6 + 行间距补 6 | 圆心 (40,40) |
| 服务商头卡头像 | 64 / 16 | 顶对齐 → 上距 = 左距 16 | alignSelf(Start) | 圆心 (48,48) |

★ **2026-10-27 参考应用像素实测**（860×1920，2.375px/vp）：参考图标 **36vp**、左留白 **15.7**、
标题左缘 **64.5**、分割线 **64.8**；本笔后本工程 **38 / 15 / 66 / 66**——图标略大 2vp（决明
「本来就打算略增大」），左留白与标题列均在 1.5vp 内。参考图标并不比原 36 大，「偏右」来自整颗
图标往里 2.1vp，不是图标尺寸。

★ **两种对齐姿势都能满足判据，按「重心」选**：①图标高度 < 容器内容高度时，**垂直居中 +
横向偏移**是首选（会话卡：居中保证上下留白对称、卡片重心不偏，代价是右侧文字整体右移一个
偏移量）；②顶对齐只在「图标本来就是该行最高元素」时用（服务商头卡右列三行 72 高于头像 64，
居中会让头像上距 20、圆心离线 4vp，故取顶对齐，代价是头像下沿比右列底部高 8）。
★ **反面先例（勿再走）**：会话卡首稿按①的顶对齐做（`alignSelf(ItemAlign.Start)`）——上圆角

上下留白是否对称，不是只看上方弧线是否顺**——这条与 §3.1 的圆心共线是两把尺子，必须同时满足。

2. **状态**：数据源须可观察——原生 V2 组件直接 `@Param` / `@Local` 即可，**无需** `enableV2Compatibility`；
   V1 壳的复杂类型（数组、选中集合）才在构造处 `UIUtils.enableV2Compatibility(this.xxx)` 传入；V2 组件
   内**禁挂 V1 装饰器**（订阅上移壳侧，值经标量 `@Param` 下行）。数组整体替换在观察链正确时即刷新；
   派生数据按需设**单一重算口**（V1 壳 = `@Watch` 汇聚到单写口，V2 = `@Computed`），不强制逐源挂
   `@Watch`。键 = 唯一稳定身份（Repeat 依键管节点身份），**禁**把状态塞回键指望键变重建来刷新。
3. **复用**：Repeat 复用节点**不触发** `aboutToReuse` / `aboutToRecycle`——业务禁靠它们重拉行数据；
   异步结果回填先核对身份（如 id 相等）再落行。`RepeatItem<T>` 整体传参（禁只传 `ri.item`）；卡内禁
   构造期快照（显示与事件一律读当前 item）。行级态（选中 / 多选 / 未读 / 显示开关 / 深浅色）由壳侧
   持标量 `@Param` 逐行下发。
4. **布局**：滚动容器内**只许一个 Repeat**（`.virtualScroll()`），each 子根用 `ListItem`（简单列表推荐；
   `ListItemGroup` 亦为合法根）；宿主须给**有限视口**（`height('100%')` / `layoutWeight`——勿用外层
   Scroll 把 List 撑成无限高）。骨架与容器观感参数（`edgeEffect(Spring)` / `scrollBar(Off)` /
   `cachedCount(n)`）照 §4.6.2 第 1 条；首末让位做进首末行 padding（或同一 Repeat 内的类型化头 / 尾 /
   提示行），**禁**在容器内混排 ListItem / ForEach / LazyForEach。**0 行提示必须有**（P0-1 不静默）。
5. **验收**：真机过 0 / 1 / 长数据三态（0 行含首拉在途 / 读取失败 / 真空，三种观感不混）、同 id 新对象
   （星标 / 标题 / 加密回写后重查）、滚动复用后点击与各交互态（多选 / 红点 / 开关）、深浅色与几何
   （卡宽 / 让位）；`cachedCount` 与让位数值按本页定（5 与 48 / 16 / 56 仅是首页实例值）。构建通过与
   静态检查**不等于**真机通过。

#### 4.6.2 细则

1. **容器**：`List({ space: CARD_SPACING }) { Repeat<T>(数据源) .each((ri: RepeatItem<T>) => {
   ListItem() { … } }) .key(…) .virtualScroll() }`，容器挂 `edgeEffect(EdgeEffect.Spring, { alwaysEnabled: true })`
   + `scrollBar(BarState.Off)` + `cachedCount(n)`。硬约束（官方「使用限制」）：**滚动容器内只许一个
   Repeat**、`List` 为支持懒加载的五类容器之一；each 子根在 List 场景用 `ListItem`（简单列表推荐；
   `ListItemGroup` 亦为合法根）。首末让位与尾部提示行做进 each 的首 / 末行 padding 与行内条件渲染，
   或同一 Repeat 内的类型化头 / 尾行（**不采用**空占位 ListItem）；**禁**在容器里与 Repeat 混排
   `ListItem` / `ForEach` / `LazyForEach` 或多个 Repeat。
2. **桥接（V1 壳 → V2 渲染件）**：Repeat **懒加载模式必须搭配状态管理 V2**（官方「不支持与状态管理（V1）
   配合使用，否则会导致渲染异常」）。数据源全在 V2 体系（`@Param` / `@Local` / `@ObservedV2`）时**无需
   桥接**；V1 `@State` 的复杂类型经 `UIUtils.enableV2Compatibility(this.xxx)` **在 V2 组件构造处**传入
   （官方建议用法 `SubComponentV2({ param: UIUtils.enableV2Compatibility(this.state) })`；「否则当变量被
   整体赋值时，需要再次手动调用」）。**V2 组件不能挂 V1 装饰器**：`@ComponentV2` 内 `@StorageProp` /
   `@Prop` / `@State` 零回流——订阅一律上移壳侧，值经标量 `@Param` 下行（先例 = 会话时间 / 会话图标
   两开关）。
3. **数据面与可观察变更**：数据源**整体替换**（重查或过滤后整赋新数组）在**观察链正确**时即刷新
   （数据源须具 V2 观察能力——原生 V2 状态，或经桥接的 V1 `@State`；观察链断，如普通成员、构造期快照，
   整赋也不刷）；**原地变更**（push / splice / 下标赋值）依赖 V2 观察链，**缺观察字段不得声称自动刷新**。
   派生数据设**唯一重算口**：V1 壳可用 `@Watch` 汇聚到单写口（先例 = `rows` / `favSegment` 两 `@Watch` →
   `syncVisibleRows` → `visibleRows`；壳内 `this.visibleRows =` 恰 1 处），V2 用 `@Computed`——不强制逐源
   挂 `@Watch`，散写多处才是病。漏观察 = 列表停旧态且静默，本机制第一失效面。官方「@Watch 回调触发时间
   是变量真正变化、被赋值的时间」⇒ 回调体内读到的是新值。
4. **RepeatItem 必须整体传参**：卡（自定义组件）收 `@Require @Param ri: RepeatItem<T>`；`@Builder` 函数
   须整参调用 `this.Card(ri)`，**禁** `this.Card(ri.item)`（官方 FAQ「按值传递，状态变量的改变不会引起
   @Builder 函数内的 UI 刷新」）。**禁构造期快照 / 普通成员缓存首帧**——显示与事件一律读 `this.ri.item`
   当前值（含菜单锚点 `.id(前缀 + this.ri.item.id)` 与事件上行）。
5. **键只写身份**：`.key((row) => row.id)`——键须为全列表唯一稳定身份（重复键行为未定义），Repeat 依键
   管理节点身份与复用。**禁**把选中 / 未读 / 时间 / 标题塞回键；也**禁**指望改键强制重建来刷新
   （官方「仅改变键值不改变 item 的情况不会触发刷新」）——旧 `ForEach` 的「键含状态后缀」机制照抄过来
   等于卡面定格。**同 id 新对象**（星标 / 标题 / 加密回写后重查）靠 item 比对刷新（官方「比较当前索引
   处节点数据 item 是否变化」）。
6. **行级态经 `@Param` 传播**：选中 / 多选 / 未读 / 两显示开关 / 深浅色等**非行数据态**由壳持有 → 标量
   （或经桥接的数组）`@Param` 逐行下发；事件回调读当前 item，禁读构造期快照。
7. **视口有界**：`.virtualScroll()` + `cachedCount(n)` ⇒ 节点数由**可视区 + 预加载区（含复用池）**决定，
   不随数据条数线性增长（官方「Repeat 根据容器组件的显示区域和预加载区域加载子组件……管理列表子组件
   节点的创建与销毁」）——**不是**「严格只留可视区那几条」。宿主须给 List 有限高度（`height('100%')` /
   `layoutWeight`），别用外层 Scroll 把它撑成无限高（有界视口是懒加载前提）。0 / 1 / 长数据三态都要
   过一遍（0 行的壳侧兜底见下条）。
8. **让位与提示行**（下列数值系首页实例值，非全局口径；新页按自身宿主让位与真机手感定）：首行 padding =
   宿主 `topPad` + 分段悬浮位 `SEGMENT_TOP_CLEARANCE 48`；末行 padding = `bottomPad` + 尾隙 16（多选中另
   加批量条让位 56）；读取失败提示行 = >0 行时随末卡尾行（同 `CARD_SPACING` 隙）、0 行时由壳侧以同一定位
   常量兜底渲染（「0 行也能见」，P0-1 不静默）。数值改动不动模板结构。
9. **复用与生命周期**：Repeat 自身复用**不触发** `aboutToReuse` / `aboutToRecycle`（官方原文；创建 /
   销毁路径的 `aboutToAppear` / `aboutToDisappear` 照常跑，**勿扩写成「任何生命周期都不跑」**）——业务
   禁靠这两个生命周期重拉行数据；异步结果（查库 / 认证 / 网络）迟到时先核对身份（id 相等）再落行。
10. **配套**：刷新链契约见 `docs/规范-数据存储获取刷新方案.md` §3（该节「ForEach 键变重建」主通道不
    覆盖 Repeat 数据源，两条互指）。
11. **重拉避开滚动（2026-11-16 退页偶发卡顿修复笔）**：长列表的 DB 重查与数据源整体替换不得落在
    用户滑动窗口。实现 = 列表容器 `onScrollStart/onScrollStop` 成对上行星侧，滚动中 `reload`
    只记一个补查意图、已经在途的回包只留最新快照，`onScrollStop` 先落快照再补查（`ChatSessionList`
    R2-c，List 与 WaterFlow 两档同契约）。**首拉 `loaded=false` 不推迟**，避免空列表被滚动位卡住。
    禁止只把退页去抖常量调大——固定延时只挪撞车位置，不能覆盖滑动时长；也禁止只拦查询不拦回包
    （查询起点早于滑动时仍会在滑中整表赋值）。

### 4.8 可拖拽列表卡四件套（2026-09-27 排序原位化落地 + 两次真机报障后立档）

> 适用判据 = **列表本身开了官方拖拽排序**（`ForEach` / `LazyForEach` / `Repeat` 挂 `.onMove`，官方限
> List/Grid 容器、每迭代一个 ListItem）。四件互不替代、缺一出真机可见缺陷——**前三条各有一次真机
> 实拍报障为据**。★ 本节的由来：这套口径原先只写在三个「独立排序页」的文件头注释里，2026-09-27
> 排序原位化把其中两页删除后，口径随之失去文档家 ⇒ 落地笔连漏两条（决明两次报障）；故立此节为
> **唯一文档家**，搬迁/新建拖拽列表一律先核本节。
> ★ 本条对第 1 条**有条件的豁免**：容器**零水平 `padding`**（窄宽由条目层 `CARD_PANEL_WIDTH` 承担）
> 时不必挂 `.clip(false)`——「水平 padding 即视口缩进」那条裁切根因不存在，视口边界 = 屏缘
> （2026-09-27 六档真机对照「原宽档」= 该几何，实测左右不裁、含阴性对照）；有水平 `padding` 的
> 容器才必须挂（先例 = 服务商页 / 助手页 / 工作区文件夹视图）。现役四处拖拽列表：三处挂、
> 记忆库页不挂（各有据；★ 2026-10-17 排队总案 U2 笔勘误：原记「三处」漏计
> `WorkspaceFolderView.ets`，见调研档 §9.3）。
> 断言锚 = `assert-ui-shape` 195 组（服务商 / 助手两页原位拖拽四件逐件入判据 + 记忆排序页 Repeat
> 机制含**本页关裁剪几何与标准卡宽**；卡壳 `stateEffect(false)` 钉**卡壳链两跳锚**而非存在钉〔挪到
> 卡内子键即红〕；第 4 条的落定映射另配**直跑真值表**〔钉 3b，2026-09-27 自检轮补〕；逐件变异恰红）。

1. **容器关裁剪**：List 挂 `.clip(false)`。
   缺它 → 长按浮起放大的卡被列表**视口边界**削成直边（左右两角被切），根因 = 水平 `padding`
   即视口缩进（坑10）。官方对 `onMove` 的预览**无任何旋钮**（`dragPreview` 一族只对 `onDragStart`
   生效，d.ts 明写），故解法只能在几何：关掉列表自身裁剪。
   ★ 与之配套：让位（顶/底留白）走官方 `contentStartOffset/contentEndOffset`（offset 属滚动内容），
   **禁**用顶/底 `padding`（= 视口缩进，卡片滚不进标题栏蒙层 = 光感空转，坑9）——此条与拖拽无关，
   但同一容器上常一并配错。
2. **条目层挂同值圆角**：`ListItem().borderRadius(CARD_RADIUS)`（与卡片圆角同值）。
   缺它 → 长按浮起后卡的四角外侧露出一圈**极淡的直角蒙层**（2026-09-27 真机实拍）。
   根因 = 拖拽预览背板按**被拖条目（ListItem）的轮廓**生成，条目是矩形则按矩形画；卡片的圆角在
   条目**内部**、盖不住条目四角。
   ★ **条目宽必须等于卡宽**（否则背板比卡宽 ⇒ 卡左右两端各露一条「蒙层」）——两种等价写法：
   ①**列表有水平 `padding`**（如服务商页 / 助手页 padding 16）：条目 100%、卡体 `width('100%')`；
   ②**列表零水平 padding**（如记忆库页）：条目挂 `CARD_PANEL_WIDTH`（配 `alignListItem(Center)`
   居中）、卡体 `width('100%')`。★ **禁在条目与卡体两处同写 `CARD_PANEL_WIDTH`**——卡体的
   `calc(100% - 32vp)` 按**父（条目）**解算 ⇒ 二次收窄成屏宽-64，且条目比卡宽、背板两端露条
   （2026-09-27 记忆库页真机报障「记忆卡短了，长按后卡两端有蒙层」实锤，即规范 §4.3 同族「双重
   收窄」在拖拽条目层的复现），断言侧配**配对钉**（条目链 CARD_PANEL_WIDTH + 卡壳链
   `width('100%')` + 卡壳链禁出现 `CARD_PANEL_WIDTH`，三者缺一即红）。

### 4.11 卡片层级纵向间距三档（2026-10-23 板块间距优化笔立档）

> 治什么：设置页真机观感「板块标题和上一板块太近」——根因 = 板块间距与卡间同值 10，分组读不出来。本节把「板块与板块 / 标题与首卡 / 卡与卡」三级间距定为三档常量（单源 = `common/Theme.ets`），新增或调整带板块标题的卡栈页先读本节。

| 档 | 常量 | 值 | 出处 |
|---|---|---|---|
| 板块 ↔ 上一板块（或页内上一独立块） | `SECTION_GAP` | **20vp** | 官方分组列表 FAQ 示例 `List({ space: 20 })`（faqs-arkui-28）；工程先例 = 模型选择半模态组间（2026-09-03 起 20） |
| 板块标题 ↔ 板块首卡/首内容 | `SECTION_HEADER_GAP` | **6vp** | 2026-09-01 起 18 页约定俗成（Theme SECTION_TITLE_FONTSIZE 注释「标题与下方控件间距 6vp」），本笔收编常量 |
| 卡 ↔ 卡（同板块内） | `CARD_SPACING` | **10vp** | 官方《设置列表卡片样式》示例 `List({ space: 10 })`；dshinhm 定稿随迁 |

- **判据**：分组要可辨，板块间距须明显大于板块内卡间距（接近性原则，≥2 倍）；标题要读作「属于下方这组」，标题下间距须小于卡间距。20:6 ≈ 3.3:1，一眼分组。
- **消费形态（结构模板，SettingsPage 版式）**：`Column({ space: SECTION_GAP })`（页面级，盛板块）→ 每板块 `Column({ space: SECTION_HEADER_GAP })`（标题 + 内容）→ 板块内多卡再包 `Column/List({ space: CARD_SPACING })`。间距一律由容器 space 管理（沿 §3 既有规则，禁对卡片挂 margin 管间距）。
- **例外一（拖拽列表静态首项形态）**：LazyForEach 长按拖拽页（MemoryLibraryPage）板块头是列表静态首项，标题与首卡随 List space = `CARD_SPACING`（10）——结构档：标题不能与首卡同 ListItem（拖拽索引域），亦禁负 margin 收缝（§4.6 负值红线）。板块间 20 已够分组，此档可接受。
- **例外二（dshinhm 定稿搜索页族）**：设置搜索页历史/最近两板块为 dshinhm 定稿随迁（标题 18 Bold + margin top 12，有效板块距 ≈22），语义等同 SECTION_GAP 档——不动；搜索交互族版式单源在 §4.7 与《规范-搜索交互》。
- **边界（不归本节管）**：①表单字段标签行（13fp 灰标签 ↔ 输入框的 6，§4.5 自有档）与卡内字段组间距（12）——是卡内排版不是板块层级；②单卡编辑页（SkillEdit/KnowledgeEdit 等）页级 Column 只盛一张卡，space 惰性；③无板块标题的平铺卡栈（功能模型页、偏好「会话与阅读」页等）只有卡间档，恒 `CARD_SPACING`，禁写字面量 10/12。
- **新页验收**：带板块标题的页，两问——板块标题上方的间距（20）是否明显大于其下方到首卡（6）？板块内卡间（10）是否小于板块间？答不出或对不上 = 没走本节常量。

### 4.12 键值井（2026-10-25 立——表单重构 UI 提案 W1 项，决明拍板采纳）

> 治什么：`请求头 / 自定义 Body / 参数 / 余额请求头` 四处都是「一行两个输入框 + 底部一条通栏添加键」，同一组数据被拆成 N 个独立框 + 一条通栏蓝键，页面被切碎。井 = **同一组键值对只占一个视觉容器**。

- **判据**：一组「键 → 值」重复行（≥1 行恒用井，**不因只有一行就退化成散框**——沿 §1.1「数据行组卡行数由数据决定，不换形」判例）。不是键值对的重复行（如「时段 → 起始/结束」三元）不套井，另议。
- **形态**：外容器 = 浅灰实底（`Theme.wellBg`，随卡底透明度档位叠 alpha）+ 圆角 12 + 0.5vp 发丝描边（`cardBorderColor`）+ 行区内距（上 4 / 下 6 / 左 6 / 右 8）；行高 36~40vp，行内 = 键（等宽 39%，`font_secondary`）+ 1vp 竖线（`cardBorderColor` 同族）+ 值（`font_primary`）；行尾圆形删除键 28vp（无底 TEXTUAL）。**「＋ 添加」键在井外**（井下方独立一行，间距 8），键形制 = 行内文字键四件套的淡彩次级档（`fallbackButton*Tinted`，字色即主蓝）——与全工程「添加」族同档，**不新开无底彩字键**（那是已否决形态，见《规范-行内按钮与光感》§1）。
  - ★ **底的上下内距不能小于圆角半径**（2026-10-25 真机反馈「第二排圆角截断内部文字」笔）：原内距上 2 / 下 2，末排离井底只有 2vp，而井圆角是 12——弧线在角落向内收，末排文字左端正好落在弧上，读作「被切了」。现改 **下 6 / 右 8**：底部 6 + 行高 40 内文字居中留的 12 = 18 > 12，末排出弧；右侧 8 护住行尾圆删键（宽 28、贴右缘）。**判据一句话：容器圆角半径 ≤ 该侧内距 + 行内文字自身留白**，任何改内距或改圆角的动作都要重算这一条。
  - ★ **井底与全站灰键底分开单源**（2026-10-25 真机反馈「灰底也不够好看」笔）：井底用 `Theme.wellBg`（浅 `#F1F3F5` = 页底同源、读作「卡上挖了一块页底」；深 `#2A2A2C`），**不用 `fallbackGrayBg`**（那是按钮/面板搜索框的灰键底，浅 `#E6E8EA` 在白卡上 1.23 偏闷、深 `#3A3A3C` 对卡面高达 **1.50** 发白）。井的边界靠 0.5vp 描边交代，不靠灰度硬撑——灰度一重就读作「脏灰」。
  - ★ **添加键在井外**（2026-10-25 真机反馈「把蓝键移出来」笔）：原形态是井底一行 + 通栏 hairline，淡蓝实底压在灰井里像个「格子」，还把井的容器感切断。移出后关系清楚：井 = 已有的键值，键 = 再加一条。井内此后**只有「键 / 值 / 删」**，不再有任何按钮行。
  - ★ **多行行型**（2026-10-25 落码新增）：值本身需要多行编辑时（自定义 Body 的 JSON 值），行内改「上排键 + 圆删、下排值 TextArea」——40vp 单行会毁掉长 JSON 的可用性。容器仍是**同一口井**，仍是「同一组键值只占一个视觉容器」，不是第二种控件。单行 / 多行由 `KeyValueWell.multiline` 一个开关切换。
- **井内输入不套输入井**：井本身是容器，行内输入框背景必须透明——`井底 + 输入井底` 双层会出灰斑。焦点态也不自绘：走官方 `TextInput` 默认焦点表现，**井容器不加 focus 描边**。
  - ★ **但内距不能为 0**（2026-10-25 真机反馈「第一条键输入框的光标被切成弧形、body 值前面的字也被弧形切割」笔）：官方 `TextInput` / `TextArea` **自带圆角**，把 `backgroundColor` 刷透明只是去掉「看得见的灰块」，组件仍按自己的圆角裁内容——内距全 0 时文字与光标起点正好落进弧线，肉眼读作「被切成弧形」。硬取值：**左右输入内距恒 10**（井容器左 6 + 输入左 10 = 16，与卡内其他内容左缘对齐），多行值上下各 4。这条是「刷透明」的**配套约束**：刷透明只解决观感，内距才解决裁切。
- **键纪律（硬）**：行的键必须绑到值本身（或稳定 key），**不得用下标**——删中间行后续行 key 不变，否则 `TextInput` 复用会显示旧内容（现存 `ProviderHeadersPanel` 头注释已踩过此坑）。
- **四个可选通道**（2026-10-25 批 3~5 落地时增；都是「调用方有额外账要记」的接缝，缺省不传即零影响）：
  | 通道 | 形态 | 谁在用 / 为什么 |
  |---|---|---|
  | `valueSecret` | 单行值改官方密码键盘 + 显隐眼 | MCP 请求头（值 = 密钥）；请求头里也有非敏感值，故**不默认打码** |
  | `rowMark` / `rowMarkWarn` | `@Prop string[]` / `boolean[]`，下标对齐行，非空则行下方一行 11fp 小字（警示走系统色） | MCP「值不回显」三态：已保存 / 值缺失 / 未设置——**只显示**，判据与文案归调用方 |
  | `onAddRow` | 添加入口下沉给调用方（缺省 = 尾部追加空行） | MCP 请求头 ≤5 组：上限拦截 + toast 是域规则，井不内置上限 |
  | `onRowRemoved` | 行已 `splice` 后回调（同一下标） | MCP 四组平行元数据（rowFromDb / rowMetaHasValue / rowHasAssetValue / oldValues）随删同步 |
  | `onRowEdited` | 任一格编辑后回调 | HTTP 模板页：改头值即重跑「占位自动发现」这条页面独有派生链 |

  ★ **行级标注必须是 `@Prop` 数组而不是函数参**（2026-10-25 落码订正）：函数型普通成员在父状态变化时不触发子件重渲（坑16 家族），标注会冻在首帧；`@Prop` 数组整组替换即刷，且不需要纪元键。
- **单源** = 新公共件 `components/KeyValueWell.ets`；消费面五处：`ProviderHeadersPanel` / `ProviderBodyPanel`（多行行型）/ `BalanceHeadersCard` / `McpServerEditPage` 请求头（带标注 + 密文）/ `HttpTemplatePage` 请求头（带编辑回执）。
- **不做**：不加第 N 层嵌套（井里再嵌井）、不在井内放除「键 / 值 / 删」以外的控件、不给井加投影。

### 4.13 选项宫格（2026-10-25 立——表单重构 UI 提案 S1 项，决明拍板采纳）

> 治什么：四选一的场景（MCP 认证四档、引擎四版本）用分段胶囊会挤成一排小字；用「四套表单全堆在页上」又会把页面撑长。宫格 = **四块瓦片，选中后原地展开对应输入**。

- **分工判据（硬，先过这条再选控件）**：**≤3 项且纯文字 → 官方分段胶囊**（`SegmentBar` / `SegmentButtonV2`）；**恰 4 项，或选项需要副行小字/价格 → 宫格**。2 项恒用分段胶囊，**禁为凑 2×2 强行四选**。
- **形态**：2×2 网格、间距 8；瓦片 minH 46、圆角 12、浅灰底（`fallbackGrayBg` 同族）、无描边；选中 = 淡彩底（`fallbackBlueBg`）+ 强调色边 + 右下角 18vp 圆勾（勾底 = 主蓝实底、勾符号白）。副行 = 等宽 10fp、`font_secondary`。
- **配色两档（`tone` 参数，2026-11-11 MCP 认证笔——决明「与协议版本 chip 同族」）**：`gray` 缺省 = 上述灰底形态（搜索引擎页在用，逐字不变）；`chip` = 与协议版本 chip 同源，未选淡彩蓝底（`fallbackBlueBg`）+ 强调档字色、选中强调蓝实底 + 白字、边恒透明、**撤圆勾**（强调实底上勾无对比，实底本身即选中态）。chip 档只改取色与勾的存废，布局、字号、行高与 `onPick` 契约与 gray 档完全一致。**取色必须走 `Theme.selectChipBg / selectChipTextColor / selectChipBorderColor` 三单源，页面禁自写色值**；新增消费面先过分工判据再定配色档。
- **性质是「选项」不是「按钮」**：照 `ModelCapsCard` 范式——无 `stateEffect` 按压光感、不接 `resolvedButton*` 四件套（依据 = 宪法「选项类 chips」排除项，宫格同属选项族）。
- **一卡最多一组**：同一张卡里出现两组宫格 = 选型错了，应拆卡。
- **单源** = 新公共件 `components/OptionTileGrid.ets`；首批消费：`McpServerEditPage` 认证四档（2026-10-25 批 4 已落；2026-11-11 起走 `chip` 配色档）、`SearchEngineDetailPage` 引擎四版本（带价格副行，2026-10-25 批 8 已落，走缺省 `gray` 档）。
- **落码实现三条**（2026-10-25 批 4，改动前先读）：
  - **半栏宽用 `calc(50% - 4vp)` + `Flex(wrap)`**，不用 Grid：Grid 在 `Scroll` 里必须显式高度，而瓦片高度随系统字号变——用 Flex 换行让高度自然长，`build` 里也不做行数算术（宪法性能红线）。
  - **未选中瓦片保留 1vp 透明边**：选中要加 1vp 强调边，若常态无边则选中时整块瓦片跳 1vp；透明边占位是布局属性，不算自绘描边。
  - **`onPick` 回传选项值、不回传下标**：下标在档位增删后会失配（宫格只允许 4 项，但引擎版本那批可能变），且选中态归父页单一真值——本件**不自行改选中态**。
  - **内容垂直居中**（2026-10-25 反馈笔）：瓦片 `Column` 加 `justifyContent(FlexAlign.Center)`——`minHeight 46` 下默认顶对齐，单行文字上方 10、下方余 6，视觉偏上；居中后主行/副行整体落几何中心。

### 4.14 价格瓦片（三价栅格，2026-10-25 立——表单重构 UI 提案 S2 项，决明拍板「可以用圆角矩形」）

> 治什么：`输入价格 / 缓存输入 / 输出价格` 三个数是**同一组**、并列读才对；原来的「标签左置 112vp + 输入框」要占三行，且标签与值被拉得很远。

- **判据**：**同一组 2~3 个短数值**并列 → 瓦片栅格；单个字段仍走「标签在上、官方输入框」（§4.5）。
  超过 3 个不并排（窄屏每格 < 90vp，数字与单位会挤），改回竖排。
- **形态**：一行 `Row({space: 8})`，每格 `layoutWeight(1)` 等分；瓦片 = 圆角 14 + 浅灰底
  （`Theme.wellBg`，随卡底透明度档）+ 内距 `{12,12,10,10}`；格内 = 标签（13fp `cardDescColor`）
  + 值行（输入框 24fp Medium 靠左 + 「元」12fp 靠右）。
- **值行几何（2026-10-25 反馈笔定值）**：`TextInput` 高 **34vp**、上下内距 **0**、左右各
  **2vp**（防首末位落进输入框自带圆角裁切线）——原 38 高叠官方上下默认内距，24fp 数字行盒
  被裁底；值行 `alignItems(VerticalAlign.Bottom)`，「元」加约 2vp 底距与数字视觉底边齐平。
  瓦片高度随之由约 82 降到约 78（标签/值间距 4）。改字号先复测裁切，禁只调高度。
- **壳在瓦片一级**：瓦片自己给底，**格内 `TextInput` 背景设透明**——官方输入框本身就是「灰底圆角
  壳」，两层灰会叠出脏斑。这与 §4.12 井内输入同一条道理（容器给底、控件透明），不是「覆写输入框
  默认形制」，视觉结果与官方默认一致。
- **占位不跟着大字号**：值 24fp 时占位必须 `placeholderFont({ size: 14 })` 压回——占位是提示不是
  值，跟着大字号走会读成已填内容。
- **单位「元」恒在场**：价格单位是「元每百万 tokens」，瓦片只写「元」；「每百万 tokens」由卡片说明
  小字交代一次（不逐格重复）。
- **落点**：`ModelPriceCard.PriceField`（主三价与谷时三价同用一格 builder，改一处两处跟随）；
  `PriceTemplateEditPage` 复用同一张卡，零额外改动。

1. **行缩进禁用 margin 写法**：Button/ListItem `width('100%') + 对称 margin` 实测蒙层与卡
   等宽缩进失效（坑23，0bce73d 像素实锤）——一律外包容器 padding 承担，组件头注释有警告。
2. **蒙层圆角与卡圆角同族单源**：两族不可混用，禁另写字面量——
   · **整卡面**（`GroupSettingCard` EntryRow 等 47 处，§4.19；2026-10-29 起 +加号半模态三卡
   3 处——一九八八笔由 HDS 分支合流入自绘）：`borderRadius` 与 build 卡体
   必须同值 = `CARD_RADIUS`（dshinhm 一七八改铁律；2026-10-26 起两者同引用，天然同值）。
   · **消息域段卡行**（标题行 / 段控制行，§4.20）：`CHAIN_STEP_PRESS_RADIUS` = 卡体圆角
   `BUBBLE_RADIUS` − 蒙层内距 `SEGMENT_PRESS_INSET`（**同心式**，2026-10-29 蒙层同心笔立；
   16 = 20 − 4，四缘露白恒 4vp）。卡圆角变更本值随动——改任一项必同步复核 333 组结构链钉、
   333 几何组同心式钉与两处行缝消费同串钉。
3. **行高固定分档勿改回自适应 padding**：48vp 自适应 = dshinhm 旧规格，2026-09-07 决明
   「纵向宽度偏窄」实锤废弃。
4. **items 普通成员 + 调用方键变重建**：GroupSettingCard.items 为普通成员（组件自身不重渲，
   坑57 家族），仅限静态配置数据；**开关行/动态行数据必须由调用方把组卡放进键含状态/纪元的

   发热点，坑16 家族），禁依赖组件内 ForEach 键单独承担跨父状态刷新（2026-09-08 真机报障
   根因：组总开关/单行点击后成员开关定格）。
5. **组卡与单卡区分**（2026-09-08 口径修订，判据细则见 §1.1）：≥2 行同质行 → 组卡；
   恰 1 行 → 单卡——开关项自绘单开关卡 / 选择控件内容卡 / 入口行 HdsListItemCard

   登记例外（更多信息；★ 2026-09-20 自检卡退役后仅余这一张），不推广；禁把 1 行开关项或控件硬塞进组卡

   存储管理」两单行组卡经决明指令合并为一张双行组卡（同域入口优先成组，§1.1 表组卡行）；
   合并后原例外项从表内退出，不视为对「独立成行」例外本身的否定（2026-09-12「记忆 +
   主动消息」合卡同此口径）。★ 2026-09-18 增**第二例外 = 卡级开关行**（助手工具页一页五卡
   各恰 1 行 Toggle，决明指令定形）——按本条字面读会误判为须转单开关卡，实际登记例外，
   照 §4.4 实施；两条例外均须逐笔登记。
6. **开关行契约**（2026-09-08 立，同日真机报障 + 决明「统一」定形）：**唯一形态 = 只点开关**
   ——Toggle 可点（Default 命中 + onChange 上行 = 唯一控制面），行不可点且 `.stateEffect(false)`
   去按压反馈；无形态开关（组件行为单一来源）。**禁**①行点击同时切换（与 Toggle 双触发）；
   ②@Prop 子组件承载行开关状态（PageShell.content 内 @Prop 下发热点，坑16 家族）；③行点击
   直接操作 Toggle 事件；④给开关行 Toggle 挂 `hitTestBehavior(HitTestMode.None)`（退回纯
   视觉形态 = 开关点不动）。显示刷新恒走调用方键变重建（红线 4）。
7. **分组折叠两区并列**（2026-09-08 立，§4.2 配套）：组头行左侧可点区与右侧 Toggle 必须是
   兄弟节点——禁把 Toggle 放进左侧可点区（点击双触发/误触折叠），禁给左侧区挂
   `hitTestBehavior(HitTestMode.None)`（会连 Toggle 一起吞掉）；**组总开关 Toggle 恒纯视觉、
   禁挂 onChange**（显示态为派生值，单行变动程序化翻转它会反噬成全组关闭——2026-09-08
   真机实锤）；折叠恒走条件渲染 + 箭头翻转 + **animateTo 切换**（2026-09-17 折叠动画笔按
   官方 FAQ faqs-arkui-769 示例落定，见 §4.2 条；本页组头仍无动画——未点名，要加走同一形制）。
   ★ 2026-09-18 分类卡重组后本红线形态在工程内暂无消费方（工具页组头行整面退役）——
   条款保留待复用，勿据以在工具页重建组头。
8. **行内可变长文本必须吃布局权重**（2026-09-23 请求日志页真机报障「日志卡有时标题过长顶出
   右边」立；坑76）：一行 = 左可变长文本 + 右固定数据项（状态 / 时间 / 动作键）时，左文本
   **必须挂 `layoutWeight(1)`**。官方口径（`ts-universal-attributes-size` layoutWeight 段
   原文）：「如果容器中有子组件设置了 layoutWeight 属性，且设置的属性值大于 0，则所有子组件
   不会再基于 flexShrink 和 flexGrow 布局」——非权重子组件先按自然尺寸占位，权重子组件吃满
   主轴剩余空间（忽略自身 width/height，保留 minWidth）。故**只写 `maxLines(1)` +
   `TextOverflow.Ellipsis` 拦不住越界**：每个兄弟各自量到「整行宽」上限，行内依次排布时总和
   仍可超出容器，把右侧数据项挤出卡右缘（坑27 家族）；裸 maxLines 仅在**该文本独占整行**时
   充分（同卡第二行 `方法 + URL` 即此形）。同笔纪律：权重接管后同行 `Blank()` 的 flexGrow
   失效（恒 0 宽，只白占一个 `space` 间隙）——撤除，右推责任移交权重。
