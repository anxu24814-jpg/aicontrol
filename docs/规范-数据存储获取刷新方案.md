# 规范 · 数据存储 / 获取 / 刷新方案（aicontrol 定稿）

> 2026-08-30 沉淀。来源 = 坑15（Key 池返回重进竞态）+ 坑16（卡片「0 模型/余额不变」
> 双根因）一整天修复链的收口 + 服务商域存储/缓存/删除全链自检。
> **适用范围**：凡「DB 数据上屏（卡片/面板/列表）+ 增删改后界面刷新 + 子页编辑返回」
> 的新页面，一律照本方案写；偏离须先在 `docs/变更记录.md` 说明理由。
> 配套：坑15/坑16 细节在 `MEMORY_DETAIL.md`；迁移两铁律在 `AGENTS.md` 开发要求节。

## 1. 存储分层（三层职责，勿混）

| 层 | 存什么 | 本项目实例 |
|---|---|---|
| RDB（relationalStore，WAL） | 一切结构化数据唯一真源 | providers / provider_models / provider_keys 元数据 / 会话 / 消息 |
| Asset Store Kit | 密钥明文唯一去处（禁落 DB/日志/toast） | `'aic.p.'+providerId+'/'+keyId`（KeyStore.ets） |
| AppStorage | ①持久选择键 ②页面级瞬态键 | ①activeProviderId/activeModelId（EntryAbility persistProp）②providerEditId |

- 表结构与迁移只在 `ChatDbMigrate.ets`：**逐级迁移 + 迁移 SQL 幂等**两铁律（升版本
  三处同步：建表 SQL / ensureSchema / 新增迁移分支）。
- Asset 与 DB 行**成对**：写序 = 先 Asset 后 DB 行（行插失败回滚资产，不留孤儿明文）；
  删序 = 先 Asset 后行（反序留「行在明文无」假条目）。范本 = `ProviderKeyDb.insertProviderKey`。
- **AppStorage 禁用于跨页刷新广播 tick**——push 页（NavDestination）内
  @StorageProp @Watch 实测不触发（坑16 hilog 取证）。

## 2. 读取与页面状态（自持有模式）

- 卡片/面板**自持有展示数据**：卡内 `@State` + `aboutToAppear` 自拉库；父只传定位用 id
  （创建期同步值）。**禁传派生显示值**——@BuilderParam content（PageShell.content）内
  组件入参 @Prop 不随父 @State 更新（三轮修复实锤，范本 = ProviderHeadCard/
  ProviderCardItem）。
- 无中间缓存层：显示 = 查库直读，DB 是单一真源，不发明内存副本。
- 连续多次赋值先算后赋（合并为一次刷新）；ResultSet 用完 close；查询有界。
- 面板需要「编辑对象 id」时：AppStorage 订阅键（providerEditId 范式）——**进入页
  aboutToAppear 入口同步写入**（父先于子面板创建，初值即正确）、**出页不清空**
  （消费方只活在本页、每次进入先覆写；出页清空 = 坑15 竞态源头，禁止）。

## 3. 刷新链（坑16 定稿：可靠原语白名单 + 禁用黑名单）

### 可用（真机/hilog 取证可靠）

1. **ForEach 键变重建**（主通道）：键含「行身份 + 纪元」，reload 成功自增 `@State epoch`
   → 整卡重建 → 卡内 aboutToAppear 重拉。范本：管理页 `row.id + '|' + cardEpoch`、
   详情页恒单例 `'head|' + headEpoch` / `'models|' + modelsEpoch`。
2. **onPop**（子页返回刷新）：`pushPathByName(name, param, onPop)` 第 3 参
   （Callback<PopInfo>，零参箭头可编译）。★ **触发条件 = 子页 pop 必带 result**
   （官方 d.ts 原文「triggered **only when the result parameter is set** in pop/
   popToName/popToIndex」；`pop(result: Object, animated?)`，result 须 Object——官方
   NOTE 禁 boolean）：
   - 保存/删除成功路径 → `pop({ saved: true })` / `pop({ deleted: true })`（先 toast
     再 pop，result 仅作触发标记；保存失败不 pop——回调不空转）。范本：
     ProviderDetailPage.save、ModelEditPage（保存+删除）、PromptEditPage；
   - 无「保存」动作的完成返回（排序页——onMove 已实时落库）→ **onBackPressed 拦截**
     官方返回链（NavDestination/HdsNavDestination 均支持，PageShell 已透传）：
     `pop({ saved: true }); return true;`。范本：ProviderSortPage；
   - 未保存/无数据变化的返回（返回键、侧滑、取消）→ 无参 pop 不触发 onPop = 无需刷新
     （预期，不要为此加 result）；
   - **死链自查**：push 挂 onPop 而子页所有 pop 均无参 = onPop 永不触发（坑17 形态，
     且必然是「注释说触发了、实际永远不触发」）——排查第一步列「push 挂 onPop 的
     调用点」清单，逐一核对子页每个 pop/popToName 签名。
   范本：ProviderPage.openDetail/onSort、ProviderDetailPage.openModelEdit、
   PromptLibraryPage.editTemplate。
3. **组件方法回调上行**（子面板事件 → 父页 epoch 自增）：回调 prop 不经 content 传播链，
   可靠。范本：BalancePanel.onQueried / ModelsPanel.onModelsChanged。
4. **卡内手动刷新键**：卡组件自身 @State 驱动自身 build（ProviderHeadCard 右上角键）。

### 禁用（实锤不可靠/有坑）

- **@Builder 值参直调显示动态文本**：按值快照，首帧后永不重渲（官方规则）。徽章/计数
  类一律 `ForEach(badges(), …, (text) => text)`（键 = 文本本身）。「复进正常、稳定后
  刷新无效」= 首帧竞争假象，见此症状先查本项。
- **@BuilderParam content（PageShell.content / bindSheet builder 组）内组件入参 `@Prop`
  不随父 `@State` 更新**：这是坑16、坑17 的共同“传播链断点”——凡父状态异步就绪/变更
  后要刷新到 content 内组件的展示值，一律用 **`@Link`（父 @State 绑定，官方写法
  `$thinkingValue`，勿写 `$this.`——编译错）** 或 **AppStorage 广播键 + @StorageProp
  自订阅**或 **卡内自持有 @State 自拉**。**禁**用 @Prop 下发热点/依赖连接态的值
  （2026-08-31 领导真机查「关闭项不显示」实锤：`offSupported` 首帧 `false` 冻结）。
- AppStorage tick + @StorageProp @Watch 做 push 页内刷新广播（不触发）。
- onShown / 页面级 @Watch 做返回刷新（多轮实测不可靠）。
- 出页 aboutToDisappear 清空共享键（坑15：销毁晚于下次进入初始化，清空成最后落笔
  覆盖新值）。

## 3.5 提示词注入配置与协议适配（2026-08-30 方案定稿，坑17/坑18 沉淀）

- 配置模型（prompt_templates v7 三列，默认值 system+head+0 = 现状行为零回归）：
  `injectRole`（system 系统身份 / user 用户身份 / assistant AI 回复身份）、
  `injectPosition`（head 系统提示位 / depth 在用户消息深度 N）、`injectDepth`（0~4；
  0 = 最新用户消息，1 = 倒数第 2 条用户消息，依此类推；不足钳位到最早 user）。
- 组合语义矩阵（组装唯一落点 = RequestCompose.composeSendMessages）：
  - system：恒系统位（既有 system 链路——Anthropic 顶层 / Gemini systemInstruction /
    Responses instructions / OpenAI messages 原样，协议层零改动）；
  - user：**拼接式**——内容并进目标 user 消息前部（`\n\n` 分隔，IN_MESSAGE 式：不产生新
    消息 → Anthropic/Gemini 交替约束与 prompt cache 断点天然规避，RikkaHub #1101 教训的
    反向实现）；
  - assistant：目标 user 之后独立消息——后邻已有 assistant → 并入其前部（merge 守卫）；
    无后邻 → 原位插入（Anthropic 即官方 prefill 语义）；UI 排除深度 0（= 注入成末条，
    Gemini 拒 + 跨模型行为不一致，删除该组合而非运行时降级）。
- 协议适配三规则（**只适配协议规格，不逐厂商特判**——协议即厂商共识）：
  ①连续同角色 merge 守卫（Anthropic「roles must alternate」/ Gemini「alternate between
  user and model」官方拒绝；OpenAI/Responses 无害，统一合并行为一致，`\n\n` 连接）；
  ②Gemini 末条必须 user（正常对话末条恒为最新提问，守卫空转；异常序列尾部 model 段
  并入最后 user 防 400）；
  ③system 不溶入各协议 messages（既有提取零改动）。
- UI：编辑页内容输入框下方 PromptInjectConfig 域件（按钮弹 openMenu 官方菜单——身份/位置
  两键；位置档含深度 1~4；身份 system → 位置键禁用且强制 head；身份 assistant → 菜单不含
  「最新用户消息前」；选中项 endIcon 勾选；THICK 官方材质随「其他控件」分项；行内按钮
  官方形制规约）。
- 引用跟随不变：模板配置修改后所有引用会话下次发送用新版（配置同行生效）。
- ★ 系统提示词语义（2026-08-30 改名复用「全局默认」→ 2026-08-31 独立页化，领导拍板
  「分开 + 内置可重置」；同日追加「取消身份/位置配置」）：系统提示词 =
  `prompt_templates.isGlobal=1` 行（prompt-global）承载，**独立页管理**（SystemPromptPage：
  内容 + 底部「恢复/保存」两键，右上角无菜单键；★ 无注入配置面板——注入三列恒默认
  system/head/0，身份/位置/深度配置仅模板（会话提示词）有）、**库页不显示**（queryTemplates
  过滤 isGlobal=0——与管理页「分开」）、**内置默认可更改可重置**（SYSTEM_PROMPT_DEFAULT
  常量；ensurePromptGlobal 兜底内置/空行填充；恢复键回内容 + system/head/0）；注入语义
  不变 = **会话未启用会话提示词时注入、启用后不注入（互斥回退）**。
- ★ 控制台助手注入封锁（2026-09-05 决明拍板；细则 = ChatPromptState.ets 头注释）：归属 =
  内置控制台助手（ASSISTANT_CONSOLE_ID）的会话提示词注入不开放——解析侧
  resolveInject 恒走归属回退（= 内置只读路由提示词，prompt 列读时联结常量；面板覆盖与
  行 promptId 两源不消费，存量引用保留不删、切回其他助手即恢复）；UI 侧 = ChatPromptSheet
  注入卡点击 toast 拒绝（openPick 单咽喉点）+ 卡状态恒显「不可用」。其余助手行为零变化。

## 3.6 会话-助手绑定与历史过滤（2026-09-01 定稿，会话绑定改造沉淀）

- **归属语义**：`conversations.assistantId` 的 `''` 与 `assistant-default` 同口径 = 默认助手
  名下（存量零迁移）；过滤口径唯一来源 = `AssistantDb.historyFilterIds`（纯函数），禁在
  SQL/调用侧另写特判。
- **当前助手** = `ACTIVE_ASSISTANT_KEY` AppStorage 持久键（写入点唯一 = AssistantPage 点卡/
  删除重置；消费方 = 历史列表过滤 / 新会话落行绑定 / 注入链新会话回退）。
- **null 三态**：`queryConversationAssistantId` 返 `string | null`——null = 会话行不存在
  （懒创建新会话）/ `''` = 行在未绑 / 非'' = 已绑；注入链（ChatPromptState.load）仅 null
  走有效绑定回退，有行分支行为不变（存量模板会话零回归）。
- **新会话绑定**：首条消息落行写有效绑定（面板覆盖 ?? 当前助手）；面板对无行会话**不落库
  只上行覆盖**（`updateConversationAssistantId` 无 0 行守卫——0 行静默丢失坑），无行「关闭
  开关」落显式默认助手 id（`''` 悬空语义不进覆盖链）。
- **删除助手 = 级联删除**（拍板硬级联）：`deleteAssistantCascade` 事务三删（messages →
  conversations → assistants）；删当前助手 → active 重置默认 + SESSION_LIST_RELOAD_KEY 广播。
- **刷新链**：切助手/删助手 → SESSION_LIST_RELOAD_KEY 广播；ChatSessionList reload 入口
  重读 active 键（自持有范式，无新机制）。

## 4. 删除与清理（成对 + 级联）- **删服务商**五步编排（范本 = ProviderPage.deletePending）：查池 keyId 集 →
  `deleteProvider` 事务级联（models + keys + price_templates + provider 四表，防孤儿行——
  价格模板随服务商隔离，2026-09-11 v28 起随删）→ `removePoolKeys` 清 Asset →
  `clearActiveSelection` 失效当前选择 → reload + toast。
- 删模型 = `deleteModel` + `clearActiveSelection`；删 Key = 先 Asset 后行。
- 内存态残留可接受判据：重启清空 + 条目数有界（轮询指针 rotationPointers 范例）；
  否则必须在删除链里成对清。
- **数据有界红线**：日志（尾部 500 行 / 落盘 1MB 自动清最旧）、搜索历史（去重移头 +
  截断上限）、错误体（只留尾部）为范本；新增缓存/日志/长文本必须设上限。
- 订阅/注册成对：任何 `on/addWatcher/persistProp 之外的全局注册`，同一次改动写好
  off/dispose（aboutToAppear 建 → aboutToDisappear 释）。

## 5. 新页面 Checklist（照单打勾）

1. 存储：新表/新列 → ChatDbMigrate 逐级 + 幂等；密钥 → Asset（禁明文落库/日志/toast）。
2. 读取：卡片自持有 @State + aboutToAppear 自拉；父只传 id；派生值禁走 @Prop。
3. 刷新：子页返回刷新 → push 挂 onPop → reload 自增 epoch；**子页保存/删除成功 pop 必带
   result**（`pop({ saved: true })`——onPop 触发条件，坑17）；无保存动作的完成返回 →
   onBackPressed 拦截 → pop 带 result；动态徽章/计数 → ForEach 键 = 文本；**禁** tick
   广播、onShown、值参 @Builder。
   ★ **PageShell.content（@BuilderParam）内组件**：父状态驱动的展示值一律 @Link /
   @StorageProp 广播键 / 自持有，**禁 @Prop**（坑16 家族——传播链断点，@Prop 只可传
   首帧快照型常量）。
4. 删除：DB 事务级联 + Asset 成对 + 当前选择失效 + reload 反馈。
5. 有界：新缓存/日志设上限；注册写好对称注销。
6. 验证：构建 0 ERROR + 真机三态（冷启动 / 热更新 / 返回立刻重进）。
